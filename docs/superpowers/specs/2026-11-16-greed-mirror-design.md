# GreedMirror（贪婪镜）设计文档

- 日期：2026-11-16
- 目标客户端：《魔兽世界：无限》（World of Warcraft: Forever，社区称 Classic+ / Camelot），Interface **16001**
- 规格来源：仓库根目录 `design.md`（用户撰写，权威）
- 状态：待用户确认后实现

---

## 1. 背景与目标

玩家在团队副本里常因"需求/贪婪"掷骰产生纠纷。国服已有一个叫 NinjaWatcher 的插件专门算"需求率"，并因此在 2026-11-14 被点名封禁。

本插件要做的是同一件事的**被动统计展示**版本：

1. 从暴雪客户端 API 读取玩家自己的 **需求次数 N**、**贪婪次数 G**、**进入 5 人副本次数 E**；
2. 按 `design.md` 的"三道关卡"算法算出**需求率**与**档位**，在**鼠标提示框**里显示；
3. 支持**手动查询**目标或自己；
4. 在**游戏 → 插件**里提供**设置页面**；
5. 对高需求率玩家（P ≥ 50%）在**队伍里相遇时**给出**只有自己可见**的提醒。

### 与被封插件的区别（决定实现边界）

| | NinjaWatcher（被封） | 本插件 |
|---|---|---|
| 用途 | 标记"全需"玩家、供人避雷 | 被动展示统计数字 |
| 玩家评价/自动标记 | 有 | **无** |
| 黑名单 | 有 | **无** |
| 聊天广播 | 有 | **无**（只用本地聊天框 `DEFAULT_CHAT_FRAME`，不 `SendChatMessage`） |
| 云端上传 | 无 | **无**（不发任何网络请求） |

`design.md` 第 60 行明确要求"只展示统计，不添加玩家评价、自动标记、黑名单、云端上传或聊天广播"，本实现严格遵守。

## 2. 目标 / 非目标 / 反目标

**目标**
- 读出 N/G/E 三个累计值，并在鼠标提示中给出需求率与档位。
- 设置页面（游戏 → 插件）可开关：插件总开关、鼠标提示、自身数据显示、详细次数。
- 每玩家独立缓存，四档查询间隔（实时 / 15 / 30 / 60 分钟），默认 60 分钟；**缓存到期后下次查看时刷新，不做后台定时扫描**。
- 设置自动保存；**缓存在重载后清空**。
- 处理限频、查询失败、快速切换鼠标目标。
- 对 P ≥ 50% 的玩家：记录姓名 + guid，队伍相遇时聊天框（仅自己可见）+ 屏幕中央横幅提示。
- 全中文界面。

**非目标（本次不做）**
- 玩家评价、自动标记、黑名单、云端上传、聊天广播、跨玩家数据分享。
- 插件商店上传、图标美术资源（用 WOW 纯文字/色块表现，不做 .tga）。
- 插件内建统计图/历史曲线。

**反目标（明确不做）**
- 不做任何形式的**后台轮询**（不 `OnUpdate` 定时全队扫描、不用 timer 定期刷新他人）。
- 不调用 `NotifyInspect` / `InspectAchievements` 等受限接口，不注册受限事件。
- 不把"读不到"当成 0；缺数据必须显示"数据不可读"。

## 4. 客户端 API 支持情况核实（先确认，再实现）

### 4.1 目标客户端

- 《魔兽世界：无限》= World of Warcraft: Forever，BlizzCon 2026 发布，2026-11-04/05 上线；内部代号 Camelot，TOC 游戏类型 `forever`（等价 `camelot`）。
- 客户端版本线 1.60.x，接口号 16001。
- wiki：`Patch 1.60.1/API changes`、`World of Warcraft: Forever`。

### 4.2 权威 API 基线

来源：`https://raw.githubusercontent.com/Thunderz96/forever-addon-kit/HEAD/data/forever_api.json`
（本地留存 `.research/forever_api.json`；client 元数据：`locale=enUS, version=1.60.1, project=1, interface=16001, build=69893`，6045 个函数名 + 269 个 `C_` 命名空间 + 11417 个 UI 帧名）

| API / 对象 | 基线中是否存在 | 用途 |
|---|---|---|
| `GetStatistic(id)` | ✅ | 读**自己**的统计；返回 `value(string), skip, id` |
| `GetComparisonStatistic(id)` | ✅ | 读**比较对象**的统计 |
| `SetAchievementComparisonUnit(unit)` | ✅ | 指定比较对象；返回 bool，触发 `INSPECT_ACHIEVEMENT_READY` |
| `ClearAchievementComparisonUnit()` | ✅ | 清除比较对象 |
| `GetStatisticsCategoryList()` | ✅ | 统计分类（用于运行时自检/兜底发现统计项 ID） |
| `GetCategoryNumAchievements(cat)` / `GetAchievementInfo(cat,i)` | ✅ | 统计项名称与 ID（运行时兜底发现用） |
| `GetNumGroupMembers()` | ✅ | 队伍扫描 |
| `NotifyInspect` / `CanInspect` / `InspectUnit` / `InspectAchievements` | ✅ | **不使用**（多余且属受限路径） |
| `TooltipDataProcessor` | ❌ | 提示框改用经典挂钩方式 |
| `Settings` 命名空间（`Settings.RegisterCanvasLayout` 等） | ❌ | 设置页改用旧式选项面板 + 兜底 |
| `C_PlayerInfo.*` 统计类、`GetNumGroupInstances`、`GetPlayerStatistics` | ❌ | **不存在** → 无"直接读他人统计"的专用 API |

### 4.3 结论：读他人数据的唯一可行链路

零售/怀旧服都**没有**"读取他人战利品统计"的专用 API。唯一可行链路就是玩家手动"点开队友的成就统计看三个数"所用的底层机制：

```
SetAchievementComparisonUnit(unit)   -- 指定比较对象（unit token）
      ↓ 服务端查询完成
INSPECT_ACHIEVEMENT_READY (guid)     -- 事件，必须与在途请求的 guid 一致才接受
      ↓
GetComparisonStatistic(1044 / 1043 / 932)
      ↓
ClearAchievementComparisonUnit()
```

服务端会**限频**：请求过多时不触发事件（`API:NotifyInspect` 文档明确"服务端可能限制请求数量，不触发事件"）。`SetAchievementComparisonUnit` 返回 `false` 表示对象不可比（通常距离过远/被限频）。

### 4.4 三条限频/失败语义（实现必须区分）

| 现象 | 判定 | 处理 |
|---|---|---|
| `SetAchievementComparisonUnit` 返回 false | 该玩家不可比 | 记为"不可查询"，对该玩家冷却一段时间，不再重试 |
| 事件超时未到 | 服务器限频吞掉请求 | 记为"限频"，指数退避后重试；提示框显示"查询超时" |
| 事件 guid 与在途请求不符 | 别的请求/别的插件抢走 | 丢弃，不写入任何缓存 |

### 4.5 无法离线验证的部分 → 运行时自检

`1044 / 1043 / 932` 是 Forever 侧统计 ID，公开资料无法离线验证语义。实现采取**双保险**：

1. **主路径**：硬编码这三个 ID 读值；
2. **自检**：进入游戏后用 `GetStatistic(1044/1043/932)` 读自己的值，检查是否为"合理的非负整数"；
3. **兜底发现**：若主路径读不出数值，则用 `GetStatisticsCategoryList()` + `GetCategoryNumAchievements()` + `GetAchievementInfo()` 枚举统计项，按中文/英文关键词（需求/need、贪婪/greed、进入副本/instance）尝试定位真实 ID；
4. 仍读不到 → 显示**"数据不可读"**，绝不用 0 顶替。

`/greed api` 斜杠命令输出自检结果（三个 ID 各自读到什么、是否走了兜底发现），供玩家自行确认。

## 5. 方案比较（Approaches）

### 方案 A：成就比较单位链路（**选中**）
- 做法：`SetAchievementComparisonUnit` → 事件 → `GetComparisonStatistic` → `Clear`。
- 优点：这是客户端唯一路径；不需要 NotifyInspect、不注册受限事件；只读、无副作用（除比较对象是全局状态）。
- 代价：比较对象是**全局单例**，同一时刻只能有一个；服务器限频；距离过远不可比。
- 结论：唯一可行，接受这些约束并围绕它做队列/冷却/超时设计。

### 方案 B：`NotifyInspect` + 解析检视面板（放弃）
- 做法：请求检视对方装备/天赋，再去读检视窗口里的统计数字。
- 放弃原因：走的是受限路径（距离限制、隐私限制、可能被封禁的"窥视"接口），且需要解析 UI 文本，脆弱且不必要——比较单位链路给的是结构化数值。

### 方案 C：只支持自己 + 手动粘贴别人数字（放弃）
- 放弃原因：不满足"鼠标提示显示目标需求率"的核心诉求。

### 方案 D（关于设置页）：三路运行时探测（**选中**）
现代 `Settings` API → 旧式 `InterfaceOptions_AddCategory` → 斜杠命令自绘面板。理由：基线显示客户端**没有** `Settings` 命名空间，但客户端是 12.1.5 血统、可能随版本补齐；运行时探测能同时适配两端，且任一路径都不会崩。

## 6. 算法规格（三道关卡，严格照 `design.md`）

输入：`N`（需求次数，统计 1044）、`G`（贪婪次数，统计 1043）、`E`（进入 5 人副本次数，统计 932）。

### 6.0 前置：可读性
三个字段**任一不可读** → 整体判定为 **"数据不可读"**（`design.md` 第 15 行），不进入后续判定。
（"不可读"含：API 返回 nil / 空串 / `-` / `—` / 非数字串 / `skip=true` / 受保护值 / `pcall` 失败。）

### 6.1 第一关：基础需求率
```
P = N / (N + G)          -- 分母不含"放弃"
N + G == 0 → "无掷骰记录"（空样本，不分类）
```

### 6.2 第二关：总活跃度门槛
```
E < 4        → "数据不足"（不分类，不提示）
T(E) = 5.4 * E
R = N + G
R < T(E)     → "低"（放弃型 / pass-type）：不计算需求率、不给出任何需求率提示、不进高需求率名单
R >= T(E)    → 进入第三关
```
> 示例：E=10 → T≈54，即 20 次全需求也会因 R=20 < 54 被判为"低"。

### 6.3 第三关：需求率分档
| 需求率 P | 附加条件 | 档位 | 颜色 |
|---|---|---|---|
| P < 10% | — | 正常 | 深绿 |
| 10% ≤ P < 30% | — | 正常 | 绿 |
| 30% ≤ P < 50% | — | 偏高 | 黄 |
| P ≥ 50% | 且 R ≥ 30 | 极高 | 红 |
| P ≥ 50% | 且 20 ≤ R < 30 | 偏高（封顶） | 黄 |

另：**R < 20 → 标记"样本少"，不做档位判定**（显示需求率但不给档位色）。
> 可达性说明：默认参数下 `R ≥ T(E)` 且 `E ≥ 4` ⇒ `R ≥ 21.6 ⇒ R ≥ 22`，故"R < 20"分支在默认参数下**不可达**；仍按规格实现（参数调整后即生效），并在自检里断言这一点。

### 6.4 高需求率名单
只有**通过第二关且算出 P ≥ 50%** 的玩家才进入名单（被第二关判为"低"的玩家没有 P，不入名单）。
名单记录 `name + guid`，**会话内有效**（见 8.3 说明）。

## 7. 界面与交互

### 7.1 鼠标提示（开关：鼠标提示 / 自身数据显示 / 详细次数）
在玩家单位提示框底部追加若干行（不改原生行）：

```
贪婪镜：需求率 42.1%（偏高）        ← 第 1 行，带档位颜色
需求 120 次 · 贪婪 165 次 · 进本 25 次   ← 第 2 行（仅"详细次数"开启时显示）
```

- 无数据时：`贪婪镜：数据不可读`（灰色）。
- 第二关判"低"：显示 `贪婪镜：未达活跃度门槛（不显示需求率）`（灰色，不给任何需求率结论）。
- E < 4：`贪婪镜：数据不足`。
- 自己：`自身数据显示`关闭时不追加任何行。
- 附加行的所有权必须可验证（行号 + 文本 + FontString 身份三重校验），原生提示框重建时立刻失效，避免写到别人的行上。

### 7.2 手动查询
斜杠命令 `/greed`（别名 `/gm`、`/贪婪`）：

| 命令 | 作用 |
|---|---|
| `/greed` | 查询自己（读自己的统计，打印到聊天框） |
| `/greed target` | 查询当前目标（`unit="target"`） |
| `/greed party` | 依次查询队伍成员（走队列，逐个显示） |
| `/greed settings` | 打开设置页面 |
| `/greed api` | API 自检：三个统计 ID 的读取结果、是否走了兜底发现、比较单位链路是否可用 |
| `/greed test` | 运行内置逻辑自测（算法/解析/缓存），输出通过数 |

### 7.3 队伍提示（P ≥ 50% 玩家）
触发时机：`GROUP_ROSTER_UPDATE` / `RAID_ROSTER_UPDATE`（**仅事件驱动**，不做后台轮询）。

- 判定：队伍成员 guid 命中名单且当前判定仍为 P ≥ 50%。
- 聊天框：`DEFAULT_CHAT_FRAME:AddMessage`（**只有自己可见**，不 `SendChatMessage`）。
  例：`[贪婪镜] 提示：<名字> 的历史需求率较高（78%），请注意沟通。`
- 屏幕中央：自绘横幅（居中 FontString + 背景板，3 秒淡出），显示 `<名字> 需求率较高`。
- 同一玩家 10 分钟内只提醒一次（防止反复组队刷屏）。
- 独立开关（我的补充，见 8.2）：`partyAlert`，默认开。

### 7.4 设置页面（游戏 → 插件）
四个必需开关 + 缓存档位下拉 + 一个补充开关：

| 项 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 开 | 总开关；关闭后不读任何 API、不显示任何东西 |
| 鼠标提示 | 开 | 玩家单位提示框附加行 |
| 自身数据显示 | 开 | 对自己也显示（关掉后只显示他人） |
| 详细次数 | 开 | 显示 N/G/E 具体数字（关掉后只显示需求率与档位） |
| 查询间隔 | 60 分钟 | 实时 / 15 / 30 / 60 分钟 |
| 队伍高需求率提示 | 开 | 我的补充开关（见 8.2） |

设置**自动保存**：改动立即生效并写入 SavedVariables，客户端在登出/重载界面时自动落盘，不设"保存"按钮。

## 8. 缓存与设置存储

### 8.1 设置存储
- SavedVariables：`GreedMirrorDB`（只存设置项）。
- 结构：`{ enabled, tooltip, selfTooltip, detailCounts, cacheMinutes, partyAlert }`，读取时逐项做类型/范围校验，坏值回落到默认值。

### 8.2 与 `design.md` 的两处偏差（我的决定，需确认）
1. **额外的 `partyAlert` 开关**：`design.md` 只列了四个开关，但"P ≥ 50% 玩家提示"是一项带"评判色彩"的功能，给它独立开关更安全（用户可随时关掉），默认开。
2. **查询间隔档位冲突**：`design.md` 第 57 行写的是"实时、15、30、60 分钟，默认 60 分钟"；最初需求（口头）写的是"实时、5、10、30，默认 10 分钟"。**以 `design.md` 为准**（用户明确"根据文档开发"），实现 0/15/30/60，默认 60。

### 8.3 缓存
- **每玩家一条记录**，键 = guid（无 guid 时回退 `名字-服务器`）。
- 记录：`{ need, greed, entries, at, source }`。
- **只存在于内存**（不进 SavedVariables）→ **重载后自动清空**，满足 `design.md` 第 58 行。
- 有效期 = 设置里的间隔档位；实时档 = 0（每次查看都重新请求）。
- 判定顺序：命中且未过期 → 直接用；命中但已过期 → **立刻发起刷新**（不后台定时），提示框先显示"查询中…"。
- **高需求率名单**同样只存内存（会话内），理由：持久化一份"谁需求率高"的名单在观感上等同于黑名单，与"不做黑名单"的约束冲突；且 `design.md` 只要求"下次在队伍内遇到"（会话内即可覆盖）。**若需要跨会话持久化，需用户明确同意。**

## 9. 限频 / 失败 / 快速切换目标

- **单一在途请求**：全局最多一个 `SetAchievementComparisonUnit` 在途；其余请求排队（上限 20）。
- **防抖**：鼠标悬停产生的请求延迟 0.4 秒再发（快速划过不会发请求）。
- **最小间隔**：两次 `Set` 之间至少 1.2 秒（保护服务器）。
- **超时**：悬停请求 5 秒、手动请求 10 秒；超时记为"限频/超时"，退避后重试。
- **不可比冷却**：某玩家返回 false 后，60 秒内不再请求该玩家。
- **快速切换目标**：每次请求带 guid 校验；事件 guid 与在途请求不符 → 直接丢弃；玩家离开队伍/失去可见性 → 取消在途请求并清比较对象。
- **战斗中不发起**：战斗中不调用比较单位 API（`InCombatLockdown()` 为真则跳过）。
- **全局比较状态保护**：`hooksecurefunc` 监听 `SetAchievementComparisonUnit` / `ClearAchievementComparisonUnit`，若别的插件或原生界面抢先改动比较对象，立刻放弃我方请求（避免读到别人的答案）。
- **原生成就比较框**：`INSPECT_ACHIEVEMENT_READY` 期间临时屏蔽原生订阅，避免原生成就窗口被我方请求弹出；请求结束恢复。

## 附：实现期裁定记录（2026-11-16，实现完成后补记）

以下为 builder-check 与实现过程中的最终裁定，正文如与之冲突以本节为准：

1. **skip 语义**：`GetStatistic` 的第二个返回值只表示“默认 UI 不显示”，不是不可读；`ReadOne` 忽略 skip（`.research/stats_api.txt` 原文佐证）。他人数据走 `GetComparisonStatistic`，本就不返回 skip，忽略可消除不对称。
2. **高需求率名单门槛**：P ≥ 50% 且已通过活跃度门槛（status == "rated"）；判为“低”的放弃型玩家即使原始 P 高也不入名单、不提示。
3. **名单持久化**：写入 `GreedMirrorDB.watchlist`（SavedVariables），跨会话保留；条目含姓名/guid/rate/时间戳。
4. **战斗策略**：被动悬停不发起请求（提示“战斗中未查询”）；手动命令可发起；在途请求进入战斗则取消（手动保留）。
5. **队伍扫描范围**：小队自动扫描 party1-4；团队只做名单提醒检查；请求队列上限 40。
6. **TOC**：`## AllowLoadGameType: camelot`（与同接口号参考实现在用一致；wiki 称 forever ≡ camelot）。
7. **设置页三级降级**：现代 Settings API → `InterfaceOptions_AddCategory` → `/greed settings` 自绘面板。
8. **探针**：`/greed probe` 输出客户端版本、接口可用性、三个 ID 的原始值/解析值/名称/校验结果、统计树条目数与按名称发现结果、运行状态。
9. **限频与失败态分级**（提示框/聊天共用）：查询中 / 数据不可读 / 不可比（距离） / 查询超时（服务端限频） / 战斗中未查询 / 成就窗口被占用 / 缺少接口 / 已取消。
10. **请求副作用控制**：单在途 + 队列 + 防抖 0.35s + 最小间隔 1.2s；hooksecurefunc 监听比较单位被外部改动即放弃请求；请求期间临时静音并恢复原生 AchievementFrameComparison 的事件订阅；请求可能弹出原生成就窗口时结束后 `HideUIPanel` 收回。
